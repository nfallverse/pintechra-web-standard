# Product Catalog Website — AI Project Instructions

## 1. Purpose

This document provides project-specific instructions for designing and building product catalog websites.

The goal is to create a product catalog that presents products clearly, communicates their value, builds trust, and helps visitors make informed decisions.

Follow the root `AGENTS.md` and all relevant design, engineering, and workflow standards.

## 2. Project Discovery

Before implementation, understand the following:

- Brand name and identity
- Product types and available products
- Target audience
- Main purpose of the catalog
- Product information and specifications
- Available product images and assets
- Contact or purchasing methods
- Required features
- Technical constraints

Do not invent product specifications, prices, certifications, testimonials, or business claims.

If essential information is missing, ask focused questions before making assumptions.

## 3. Information Architecture

Consider the following structure based on project needs:

- Home / Catalog Overview
- Product Listing
- Product Detail
- About the Brand
- Contact / Inquiry

Not every project requires every page.

Keep navigation simple and make product discovery intuitive.

## 4. Product Presentation

Every product should communicate:

- Product name
- Product image
- Short description
- Main benefits
- Key specifications
- Available variants, if applicable
- Price or inquiry information, if provided
- Call to action

Prioritize accurate information and clear visual hierarchy.

Use real product images whenever available. Never replace real product photography with unrelated stock images.

## 5. Visual Direction

Establish a project-specific art direction before designing.

Consider:

- Brand personality
- Target audience
- Product characteristics
- Market positioning
- Typography
- Color system
- Layout and composition
- Image treatment

Do not force every catalog website into the same visual style.

Neumorphism may be used selectively when it supports the brand and improves usability.

Avoid excessive cards, unnecessary gradients, decorative effects, and generic AI-generated layouts.

## 6. User Experience

The website should make it easy to:

- Browse products
- Understand product differences
- View product details
- Find relevant information
- Contact the business or inquire about a product

Use clear navigation, meaningful calls to action, and consistent interaction patterns.

## 7. Engineering Requirements

Follow the engineering documentation in this repository.

Important requirements:

- Semantic HTML
- Reusable components
- Responsive layouts
- Accessible interactions
- Optimized images
- Clean and maintainable code
- Secure handling of user input
- Appropriate SEO metadata

Choose the technology stack based on project requirements rather than personal preference.

## 8. Quality Assurance

Before delivery, verify:

- Product information is accurate.
- All product images load correctly.
- Navigation works.
- Product details are readable.
- Calls to action work.
- Layouts work across screen sizes.
- Accessibility requirements are considered.
- Performance is acceptable.
- No placeholder content remains unintentionally.

## 9. AI Delivery Requirements

Before building:

1. Review the project requirements.
2. Identify missing information.
3. Define the creative concept.
4. Establish art direction.
5. Plan the information architecture.
6. Propose the implementation approach.

During development:

- Explain important technical decisions.
- Keep the implementation consistent with the approved direction.
- Avoid unnecessary complexity.

After development:

- Perform quality assurance.
- Report completed features.
- Identify known limitations.
- Provide clear instructions for running and maintaining the project.
